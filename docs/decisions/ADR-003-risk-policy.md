# ADR-003: 위험 행동은 3단계로 통제한다

## 상태

- status: accepted
- date: 2026-05-15

## 배경

자동화 테스트가 실제 결제, 외부 발송, 데이터 삭제, 권한 변경 같은 위험 행동을 무검토로 실행하면 운영 사고로 이어질 수 있다.

GPT가 생성한 실행계획에 위험 행동이 포함될 가능성이 있고, 사용자가 미처 인지하지 못한 위험도 존재한다.

## 선택지

### 선택지 A — 실행 직전 차단만 사용

Runner가 실행 직전에만 위험 행동을 검사한다. 구현이 간단하지만 사용자가 검토 시점에 위험을 인지하지 못한다.

### 선택지 B — 생성 전 지침 + 실행 직전 차단

프롬프트에 위험 행동 지침을 포함하고 실행 직전 한 번 더 검사한다. 두 단계 통제로 어느 정도 안전하다.

### 선택지 C — 3단계 통제 (생성 전 지침 + 생성 후 검증 + 실행 직전 차단)

프롬프트에 위험 행동 지침, 실행계획 import 시 키워드 검증, 실행 직전 최종 차단을 모두 적용한다.

## 결정

선택지 C를 채택한다.

## 이유

위험 행동은 한 단계 통제만으로 충분히 막을 수 없다. LLM은 지침을 따르지 못할 수 있고, 사용자는 검토 시점에 위험을 놓칠 수 있다.

3단계 통제는 다음과 같다.

1. **생성 전 지침**: 프롬프트에 허용/금지 액션과 리스크 플래그 정의를 포함한다.
2. **생성 후 검증**: 실행계획 import 시 위험 키워드를 탐지하고 리스크 수준을 보정한다. GPT가 플래그를 누락해도 앱이 보완한다.
3. **실행 직전 차단**: Runner가 step 실행 직전 PROHIBITED를 차단하고 HIGH는 명시 승인을 요구한다.
